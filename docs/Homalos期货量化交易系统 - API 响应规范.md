# 📑 Homalos 期货量化交易系统 - API 响应规范

## 1. 响应数据结构

所有接口响应均采用统一的 JSON 格式，结构如下：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": 1691234567890,
  "trace_id": "a1b2c3d4e5"
}
```

### 字段说明

| 字段        | 类型   | 必填 | 说明                                |
| ----------- | ------ | ---- | ----------------------------------- |
| `code`      | int    | 是   | 返回码：0 表示成功，非 0 表示失败   |
| `message`   | string | 是   | 返回消息，简要说明结果              |
| `data`      | object | 否   | 业务数据，具体结构由接口定义        |
| `timestamp` | int    | 是   | 服务器响应时间戳（毫秒）            |
| `trace_id`  | string | 是   | 全局链路追踪 ID，用于日志与监控系统 |

------

## 2. 返回码规范

### 2.1 通用返回码

| code | message      | 说明                 |
| ---- | ------------ | -------------------- |
| 0    | success      | 成功                 |
| 1001 | 参数错误     | 请求参数不合法或缺失 |
| 1002 | 鉴权失败     | token/签名无效或过期 |
| 1003 | 权限不足     | 用户无权限访问该资源 |
| 1004 | 请求过于频繁 | 触发限流             |
| 1005 | 数据不存在   | 资源未找到           |
| 1006 | 系统繁忙     | 服务内部异常         |
| 1999 | 未知错误     | 未捕获异常           |

------

### 2.2 行情模块（Market）返回码（2xxx）

| code | message          | 说明                                       |
| ---- | ---------------- | ------------------------------------------ |
| 2001 | 合约不存在       | 请求的合约 symbol 无效                     |
| 2002 | 行情数据延迟     | 数据落后于交易所                           |
| 2003 | 不支持的行情类型 | 请求的行情类型无效（如 tick/kline/level2） |
| 2004 | 订阅已存在       | 重复订阅同一合约行情                       |

------

### 2.3 交易模块（Trade）返回码（3xxx）

| code | message       | 说明                           |
| ---- | ------------- | ------------------------------ |
| 3001 | 下单失败      | 委托请求未被接受               |
| 3002 | 撤单失败      | 指定订单无法撤销               |
| 3003 | 资金不足      | 可用资金不足以下单             |
| 3004 | 超过风控限制  | 下单违反系统风控规则           |
| 3005 | 无效的订单 ID | 订单 ID 不存在或不属于当前用户 |

------

### 2.4 风控模块（Risk）返回码（4xxx）

| code | message        | 说明                   |
| ---- | -------------- | ---------------------- |
| 4001 | 风控检查未通过 | 触发风控规则，阻止操作 |
| 4002 | 风控配置缺失   | 系统风控参数未配置     |
| 4003 | 风控服务不可用 | 风控引擎故障           |

------

### 2.5 策略模块（Strategy）返回码（5xxx）

| code | message        | 说明                   |
| ---- | -------------- | ---------------------- |
| 5001 | 策略未找到     | 指定的策略不存在       |
| 5002 | 策略运行错误   | 策略内部异常           |
| 5003 | 策略参数无效   | 配置参数缺失或不合法   |
| 5004 | 策略被风控阻止 | 策略操作被风控系统拦截 |

------

### 2.6 数据中心模块（DataCenter）返回码（6xxx）

| code | message        | 说明                   |
| ---- | -------------- | ---------------------- |
| 6001 | 数据中心启动失败     | 据中心启动失败       |
| 6002 | 数据中心运行错误   | 数据中心内部异常           |
| 6003 | 数据中心参数无效   | 配置参数缺失或不合法   |

------

## 3. 成功响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "symbol": "rb2501",
    "price": 3580.5,
    "volume": 25
  },
  "timestamp": 1691234567890,
  "trace_id": "a1b2c3d4e5"
}
```

------

## 4. 错误响应示例

```json
{
  "code": 3003,
  "message": "资金不足",
  "data": null,
  "timestamp": 1691234567999,
  "trace_id": "f6g7h8i9j0"
}
```

------

## 5. 设计要点

1. **外壳固定**：统一的 `code/message/data/timestamp/trace_id`，便于前后端解析。
2. **模块独立错误码段**：避免冲突，方便快速定位。
3. **trace_id 强制返回**：结合日志（loguru）实现全链路追踪。
4. **data 灵活扩展**：不同接口可返回不同结构。
5. **业务与系统错误分离**：例如参数缺失（客户端问题）与系统异常（服务端问题）区分清楚。

------
